# Stage 3 Performance Report

## Scope

This report summarizes CPU Release benchmark behavior for Stage 3 modules.
The goal is to understand bottlenecks, not to claim production-ready speed.

## Measurement Contract

The current self-contained C++ harness uses one warmup and reports median
latency: five measured runs in quick mode and three in `--full` mode. File I/O
is outside the timed region. Module benchmarks allocate their main buffers
before timing; `bench_pipeline` includes intermediate-buffer allocation inside
`run_pipeline_single`.

The committed CSV tables below were generated by an earlier harness that used
one to three runs and selected the best time. Treat them as legacy evidence for
order-of-magnitude and relative trends. They must be regenerated before quoting
the updated median methodology.

Recorded environment for the legacy Week 4 run:

- CMake 3.30.5, Ninja 1.12.1, MinGW.org GCC 9.2.0
- Release build
- 32-bit local MinGW toolchain

The repository does not record a reliable CPU model/core-count snapshot for
these CSV files. Therefore results must not be generalized to ARM, NEON,
mobile SoCs, or other desktop CPUs.

## Current Harness Smoke Verification

On June 18, 2026, the updated harness was compiled and smoke-tested on:

- Intel Core i3-12100F, 4 cores / 8 logical processors
- MinGW.org GCC 9.2.0, CMake 3.30.5, Ninja 1.12.1
- Release build
- one warmup, five measured runs, median latency
- synthetic float input; no file I/O

Representative results:

| Case | Size | Median ms |
|---|---:|---:|
| bilateral direct | 128x128x1 | 47.325 |
| bilateral LUT | 128x128x1 | 38.718 |
| bilateral direct | 256x256x1 | 188.478 |
| bilateral LUT | 256x256x1 | 155.599 |
| pipeline gaussian + global Reinhard | 640x360x3 | 134.122 |
| pipeline gaussian + Reinhard LUT | 640x360x3 | 158.343 |
| pipeline local Reinhard | 640x360x3 | 1446.478 |

This smoke run verifies the new measurement path. It does not replace a full
1080P/4K regeneration, and it also shows why one run should not support a
universal claim such as “LUT is always faster”: the integrated 640x360 pipeline
LUT case was slower than float Reinhard on this run.

## Tone Mapping

| Method | Curve | Mode | Size | Time ms |
|---|---|---|---:|---:|
| float | Reinhard | luma | 1920x1080 | 50.117 |
| LUT 12->12 | Reinhard | luma | 1920x1080 | 47.524 |
| float | S-curve | luma | 1920x1080 | 350.182 |
| LUT 12->12 | S-curve | luma | 1920x1080 | 58.136 |
| float | S-curve | luma | 3840x2160 | 1404.841 |
| LUT 12->12 | S-curve | luma | 3840x2160 | 205.724 |

Interpretation:

- Reinhard is already cheap, so LUT speedup is modest.
- S-curve benefits strongly because the LUT removes per-pixel `exp`.
- Luminance-preserving mapping still pays for luma, division, and RGB scaling.

## Local Tone Mapping

| Base filter | Radius | Size | Time ms |
|---|---:|---:|---:|
| box | 5 | 640x360 | 362.176 |
| box | 9 | 640x360 | 1004.940 |
| bilateral | 3 | 640x360 | 1910.705 |
| bilateral | 5 | 640x360 | 4456.885 |
| box | 5 | 1920x1080 | 3330.083 |
| bilateral | 1 | 1920x1080 | 3016.261 |

Interpretation:

- direct local filters scale with `(2r+1)^2`
- bilateral adds range weight computation per neighbor
- naive LTM is useful for correctness and halo analysis, but needs guided
  filter, bilateral grid, pyramid, SIMD, threading, or GPU acceleration for
  deployment
- without perf/VTune counters, the compute/cache explanation is a complexity
  and scaling inference, not a measured cache-miss diagnosis

## Integrated Pipeline

Small synthetic 160x96 scene:

| Case | Pipeline ms |
|---|---:|
| gaussian + global TM | 43.24 |
| gaussian + LUT TM | 25.36 |
| gaussian + local TM | 103.72 |
| HDR merge + local TM | 126.64 |

This confirms the expected shape: local base estimation dominates the small
pipeline, while LUT TM is cheaper than float global TM in this setup.

`benchmarks/bench_pipeline.cpp` now provides a C++ benchmark entry for the same
pipeline family. Default mode runs small/preview sizes for quick smoke checks;
`--full` runs 1080P and 4K synthetic scenes.

```powershell
.\stage3_cpp_isp\build\bench_pipeline.exe
.\stage3_cpp_isp\build\bench_pipeline.exe --full
```
