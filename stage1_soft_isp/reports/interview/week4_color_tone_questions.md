# Week 4 面试题：CCM、Tone Mapping、Gamma 与显示编码

本周面试目标是讲清颜色映射、动态范围映射和显示编码是三个不同问题，并能说明每一步的数据域、顺序、数值风险和验证方法。

## 1. AWB 和 CCM 有什么区别？为什么不能互相替代？

### 核心回答

AWB 主要通过通道增益修正光源白点，使中性物体的 R/G/B 响应更接近中性。CCM 用 3×3 矩阵混合通道，将设备相关 camera RGB 映射向目标颜色空间，修正传感器滤色片串扰和色相关系。

```text
AWB: [R,G,B] * [gR,gG,gB]
CCM: [R',G',B']^T = M [R,G,B]^T
```

对角 gain 只能独立缩放通道；CCM 的非对角项可以让输出 R 使用输入 G/B，因此能改变色相和通道串扰。

### 错误后果

AWB 错会使白点和整体色温错误；CCM 错可能让中性区域尚可但肤色、红色、绿色等色相系统性偏移。用 CCM 强行补错误 AWB，通常会让不同场景表现不稳定。

### 验证

AWB 看中性 ROI 和 gain；CCM 看 identity 测试、单像素手算、负值/clip 比例，并在真实标定条件下看 ColorChecker DeltaE。

## 2. 为什么代码常写 `rgb @ ccm.T`？矩阵方向错会怎样？

### 核心回答

数学公式常把像素写成列向量：

```text
y = M x
```

NumPy 图像通常把每个像素存成最后一维的行向量，批量计算时相应写成：

```python
rgb_out = rgb_in @ ccm.T
```

是否转置取决于矩阵和像素的存储约定，不能死记代码。最可靠的方法是明确矩阵每一行/列代表哪个输出通道，并手算一个像素。

### 错误表现

若矩阵不是对称矩阵，漏转置会产生完全不同的颜色混合，常伴随系统性色偏、负值和高比例 clipping；identity 矩阵无法发现转置错误，因此还要用非对称测试矩阵。

### 最小测试

构造单像素 `[R,G,B]` 和非对称 3×3 矩阵，分别手算三个输出通道，与代码结果逐项比较。

## 3. 为什么 CCM 必须在线性 RGB 上执行？

### 核心回答

CCM 假设通道值可以进行线性组合，近似代表光响应比例。Gamma/OETF 后码值是非线性的，同样的数值差不再代表同样的光强差，矩阵混色失去原本的颜色空间意义。

### 做错后的后果

若先 Gamma 再 CCM，不同亮度区域会得到不一致的颜色修正：同一物体可能在暗部和亮部呈现不同色相，矩阵也无法用标准线性标定方法解释。

### 验证

报告每个阶段的 linear/nonlinear 状态；用同一矩阵分别在线性域和 OETF 后数据上运行，固定中灰与高亮像素观察差异。测试不能只看输出范围，还要检查颜色比例是否随亮度异常变化。

## 4. CCM 从哪里来？为什么 metadata 简化矩阵不是产品级标定？

### 核心回答

CCM 可以来自 DNG/camera metadata、标准色卡拟合或不同色温下的多套标定。产品常在已知光源下拍摄 ColorChecker，根据相机响应和目标颜色拟合矩阵，并处理白点、色温插值、定点量化和色域外值。

本项目使用 rawpy/DNG 暴露矩阵的简化形式来演示矩阵校色流程。它能验证数据流、矩阵方向和数值行为，但不等于完整 DNG 色彩管理，也不等于标准光源下的色卡标定。

### 必须说明的约定

- 矩阵的输入/输出颜色空间和方向；
- shape 是 3×3、3×4 还是其他 API 形式；
- 白点和适用色温；
- 负值、超过范围值如何处理；
- float 与 fixed-point 的缩放约定。

## 5. Tone Mapping 和 Gamma 有什么区别？

### 核心回答

Tone Mapping 解决动态范围映射：怎样把场景或线性 RGB 的宽亮度范围压入有限显示范围，同时决定高光、暗部和局部对比。

Gamma/OETF 解决显示编码：把已经位于显示范围内的线性值编码成非线性码值，以匹配标准和提高暗部码值利用率。

```text
Tone: wide linear range -> bounded linear/display-referred range
OETF: bounded linear value -> nonlinear output code
```

### 为什么不能互换

Gamma 可以让画面视觉上变亮，但不能有选择地恢复被截断的高光或设计高动态范围压缩。Tone Mapping 决定“保留什么亮度关系”，OETF 决定“怎样编码这些关系”。

### 错误表现

漏 Tone 可能高光硬截；过强 Tone 可能发灰或丢局部对比；漏 OETF 的线性图显示偏暗；重复 OETF 会泛白并破坏中间调。

## 6. `gamma=2.2` 和 sRGB OETF 有什么区别？

### 核心回答

简单 power gamma 常写作 `y=x^(1/2.2)`。sRGB OETF 是分段函数：低亮度使用线性段，较高亮度使用带 offset 的幂函数。两者趋势相近，但暗部和断点附近不完全相同。

### 为什么要区分

学习版 power gamma 适合建立非线性编码直觉；若声称输出是标准 sRGB，就应使用标准 OETF、明确输入归一化范围，并处理负值和超过 1 的值。

### 验证

至少检查 `x=0`、线性段断点附近、中灰和 `x=1`；画完整曲线，并验证输出单调、有界。只比较最终 PNG 很难发现暗部曲线差异。

## 7. CCM 或 Tone 后为什么会出现负值、超过范围和色域外值？怎样处理？

### 核心回答

CCM 含负系数和通道混合，合法输入也可能产生负值或超过白电平；Tone 参数和归一化也可能让局部超出目标范围。这些值既是数值风险，也是矩阵、白点或场景超出标定范围的信号。

### 处理策略

- hard clip：简单稳定，但可能丢色相和高光层次；
- soft clip：过渡平滑，但需要明确曲线和 tuning；
- gamut mapping：尽量保持感知色相/亮度，工程更复杂；
- 重新标定或约束矩阵：从源头减少不合理越界。

### 验证

在 clip 前统计负值比例和超过范围比例；分别查看肤色、高饱和颜色和高光 ROI。不能 clip 完再说“一切都在范围内”，那会掩盖上游问题。

## 8. 如果最终图偏色、偏暗或高光发灰，你会怎样按数据域排查？

### 排查顺序

1. 确认 Demosaic 输出是线性 camera RGB，pattern 和结构正确。
2. 检查 AWB gain、中性 ROI 和应用后 clipping。
3. 将 CCM 切换为 identity；若色相异常消失，检查矩阵方向、来源和白点。
4. 保存 Tone 前线性数据，画 Tone 曲线和亮度百分位。
5. 比较 linear display、Tone 后线性显示、power gamma 和 sRGB OETF。
6. 检查是否重复 Gamma、过早转 uint8 或不同阶段使用了不同归一化。

### 现象映射

系统性色相偏差优先看 AWB/CCM；整体线性图偏暗可能只是未编码；高光发灰或层次压缩优先看 Tone；暗部泛白常见于重复 OETF、black level 残留或过强曲线。
