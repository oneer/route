# Week 6 面试题：综合验收、故障诊断与产品级差距

本周面试目标是把前五周的模块知识组织成系统能力：能独立实现、保存证据、诊断失败，并准确说明学习版 Soft-ISP 与产品级 ISP 的差距。

## 1. 怎样证明自己真正掌握了阶段一，而不是只会运行现成脚本？

### 核心回答

掌握的证据应来自独立实现和可复核过程，而不是最终 PNG。至少包括：

- 在空目录中完成简化 RAW-to-RGB Pipeline；
- 能说明每一步的输入输出、shape、dtype、range 和 linear/nonlinear 状态；
- 为 BLC、Demosaic、AWB、CCM 等写合成单元测试；
- 保存至少三个中间结果；
- 做一组参数预测和扫描；
- 解释一个真实失败案例及修复过程；
- 留下分阶段 Git 提交和简洁报告。

### 为什么这些证据有效

独立实现检查理解，单元测试检查边界，参数预测检查因果认识，失败案例检查调试能力，Git 记录检查过程是否可追溯。任何单一证据都不足以替代其他部分。

## 2. 动态 DPC、静态 defect map 和 hybrid DPC 有什么区别？

### 核心回答

| 方法 | 信息来源 | 优点 | 风险 |
|---|---|---|---|
| 动态 DPC | 当前帧同色邻域统计 | 能发现未登记或随条件出现的异常 | 可能误伤强边缘和纹理，结果随场景变化 |
| 静态 defect map | 工厂或暗场标定坐标 | 稳定、计算简单、不依赖场景纹理 | 无法覆盖新增、温度相关或未标定坏点 |
| Hybrid | 先静态修复，再动态检测残余 | 兼顾稳定缺陷和未知异常 | 流程、阈值和重复修复更复杂 |

### 项目边界

本项目的小型静态 map 用于理解行为，不是工厂标定表。真正产品 map 需要设备级标定、坐标版本、温度/曝光条件和持久化管理。

### 验证

对固定缺陷看静态命中率，对未知注入点看动态 recall，对强边缘看 false positive，并检查两阶段是否重复修改同一位置。

## 3. Week 6 的 synthetic flat-field / mesh LSC 实验证明了什么？没有证明什么？

### 证明了什么

- 可以从受控平场构建低分辨率 mesh gain；
- mesh 插值、四通道应用、中心归一化和 clip 流程可运行；
- 在生成模型范围内可以比较校正前后残差。

### 没有证明什么

- 没有证明真实光源完全均匀；
- 没覆盖不同焦距、光圈、色温、温度和 sensor 个体；
- 没证明边缘噪声、坏点和量化在产品条件下满足要求；
- 不能把合成恢复误差称为真实相机 LSC 精度。

### 面试表达

这是流程闭环和算法 sanity check。产品级结论需要真实均匀白场、多帧平均、四通道残差、重复性和环境条件矩阵。

## 4. 怎样公平比较 Bilinear、OpenCV Bilinear 和 Edge-aware Demosaic？

### 核心回答

比较前必须固定：同一 BLC/DPC/LSC 输入、Bayer pattern、方向、白电平、输出线性范围、边界裁剪和后续显示映射。否则差异可能来自预处理或 Tone，而不是 Demosaic。

评价应同时包含：

- 常量图和采样值保留等正确性测试；
- 斜边、文字、树枝、网格 crop；
- zipper、false color、moire、blur 等主观标签；
- 对齐后的局部指标或差异图；
- 运行时间和边界行为。

### 命名边界

OpenCV edge-aware 只能按其实际 API/实现称呼，不能因为“看起来更高级”就叫 AHD。Malvar/AHD 若没有实作或接入，只能作为理论延伸。

## 5. Gray World、White Patch 和 Gray ROI 各自假设什么？

### 核心回答

| 方法 | 假设 | 适合 | 典型失败 |
|---|---|---|---|
| Gray World | 场景平均反射接近灰色 | 颜色丰富的自然场景 | 大面积单色、混合光 |
| White Patch | 最亮可靠区域接近白色 | 有可信中性高光 | 彩色高光、饱和通道、镜面反射 |
| Gray ROI | 可筛出低饱和中性候选 | 存在足够灰点且筛选可靠 | 无中性物、阈值过严、肤色被误选 |

### 公平验证

记录有效像素覆盖率、gain、gain 上限命中、应用后 clipping 和中性 ROI 误差。某方法让全图均值更接近 1，不等于它在真实中性物体上更准确。

### 产品级差距

实际 AWB 还要考虑色温估计、肤色保护、场景分类、多光源、历史平滑和视频时序稳定性。

## 6. 当前 CCM DeltaE 实验为什么不是标准 ColorChecker DeltaE？

### 核心回答

标准色卡 DeltaE 需要已知色块、标准光源/观察条件、明确颜色空间转换和目标 Lab 值。当前项目比较的是输出与 rawpy reference 的颜色差异，reference 自身包含一条渲染策略，也没有标准色块真值。

### 能支持的结论

可以观察启用/关闭 CCM 后，输出相对固定 rawpy reference 的颜色差异趋势；可以定位哪些图像区域变化较大。

### 不能支持的结论

不能声称矩阵达到某个真实色准等级，也不能跨相机、光源或任意渲染配置比较。

### 怎样升级

拍摄 ColorChecker，固定光源和曝光，提取色块线性响应，完成白平衡和矩阵拟合，再转换到约定 Lab 空间计算 DeltaE，并保留训练/验证色块或不同光源测试。

## 7. 主观问题标签怎样定义才具有可重复性？

### 核心回答

标签不能只写“更好看”，应绑定现象、区域和严重度。例如：

| 标签 | 定义示例 | 观察区域 |
|---|---|---|
| color_cast | 已知中性区域持续偏红/绿/蓝 | 灰卡、白墙、中性物体 |
| zipper | 斜边呈周期性锯齿亮暗 | 文字、建筑边缘 |
| false_color | 无真实颜色来源的彩色边 | 黑白高对比纹理 |
| shadow_clip | 暗部多级纹理合并为 0 | 固定暗部 ROI |
| highlight_clip | 一个或多个通道达到上限并丢层次 | 灯光、天空、反光 |
| over_smooth | 纹理被抹平 | 毛发、叶子、织物 |

需要固定 crop、缩放比例、显示条件和严重度量表；最好由多名观察者或至少重复评审。自动标签可作筛查，不能替代明确协议。

## 8. 如果一张陌生 DNG 最终输出严重偏色，你会怎样系统排查？

### 排查顺序

1. **输入合同：** visible area、Bayer pattern、black/white level、orientation。
2. **RAW 前端：** BLC 是否 per-position；DPC 是否误伤；LSC 是否通道/坐标错位。
3. **Demosaic：** 暂停 AWB/CCM，检查真实采样值、结构和周期性色彩。
4. **AWB：** 检查 estimation 与 application，gain 是否极端、中性 ROI 是否改善、是否发生单通道 clip。
5. **CCM：** 切换 identity，检查矩阵 shape、方向、白点和越界比例。
6. **Tone/OETF：** 检查是否在错误数据域处理、是否重复编码或通道顺序错误。

### 为什么按这个顺序

先验证上游数据解释，再验证局部模块，最后看显示编码。上游错误会向下游传播；从最终 PNG 反向调 Tone 或 CCM，可能只是在掩盖根因。

## 9. 如果把学习版 Soft-ISP 推向产品级，最优先补什么？

### 回答框架

优先级取决于目标设备和画质问题，但通常先补证据与基础能力，而不是盲目增加模块：

1. 真实标定数据：dark frame、flat-field、ColorChecker、不同 ISO/曝光/色温。
2. 更强 Demosaic 与 RAW 降噪，并建立固定伪影 crop 库。
3. AWB 场景鲁棒性和视频时序稳定。
4. 模块级性能、内存、定点量化和硬件约束。
5. 可版本化 tuning、回归数据集和自动质量门禁。

### 面试边界

学习版已经证明数据域、模块顺序和验证方法；产品级要求跨设备、跨场景、跨时间稳定，并满足性能和标定协议。两者不是“再多写几个算法”的差别。

## 10. 你会怎样用 5 分钟介绍整个阶段一项目？

### 推荐结构

1. **目标：** 从真实 DNG 搭建可解释、可测试的基础 Soft-ISP。
2. **链路：** RAW contract → BLC → DPC → 学习版 LSC → Bilinear Demosaic → Gray World AWB → metadata 简化 CCM → Tone → Gamma/OETF。
3. **验证：** 合成测试、中间 JSON/图像、坏点注入、参数扫描、局部 ROI、消融和 rawpy baseline。
4. **失败案例：** 讲一个 pattern、AWB 或 DPC 的真实诊断过程。
5. **边界：** synthetic flat-field、相对 rawpy DeltaE 和学习版算法不等于产品标定。
6. **下一步：** 真实标定、更强 Demosaic/降噪、时序稳定和性能量化。

### 面试加分点

不要逐个念模块名称。选择一条因果主线，例如“如何防止 RAW 单点错误经过 Demosaic 扩散”，或“如何保证每个结论都有代码—参数—产物—测试证据”。
