# darktable

## 深度阅读目标

读 darktable 不要试图从 main 函数一路追完整流程，那会很快迷路。它适合用来学习成熟 RAW/摄影软件如何组织“非破坏式处理管线”。你要重点看三件事：图像操作模块如何注册，参数如何保存和传递，CPU/OpenCL 双路径如何共存。

## 初学者应该先读哪些概念

darktable 的核心不是某个单独算法，而是 develop pipeline。用户每次调曝光、曲线、降噪，软件保存的是模块参数和处理历史，而不是直接覆盖原图。这和 stage1/stage3 的实验报告非常像：输入图像、模块版本、参数、输出结果必须能追溯。

## 读代码的具体顺序

建议按这个顺序：

1. 先从用户手册理解曝光、色彩、降噪、tone mapping 这些模块在界面中的含义。
2. 到 `src/iop/` 选择一个简单模块，例如 exposure 或 tone curve，不要一开始读复杂降噪。
3. 找模块的参数结构体，理解哪些参数会进入 pipeline。
4. 找 CPU process 函数，理解每个像素或每个 tile 如何处理。
5. 如果有 OpenCL 版本，再对照 GPU kernel 看同一算法如何改写。

## 对本项目最有价值的工程点

第一是参数可追溯。stage1/stage3 目前更多是脚本和报告，后续可以学习 darktable，把每次 pipeline 的模块参数保存为统一 JSON/YAML。

第二是模块边界。darktable 的 iop 模块很适合对照 stage3 的 C++ 算子：每个模块需要参数、输入输出、处理函数、元数据和可选加速路径。

第三是非破坏式思想。本项目所有实验都应能从原始输入重新生成，而不是只保存最后图片。

## 可迁移练习

1. 给 `stage3_cpp_isp` 的 pipeline 输出增加一份 manifest：输入文件、模块顺序、参数、commit hash、输出路径。
2. 为 tone mapping 模块设计一个参数结构体，避免散落在命令行参数中。
3. 选择 darktable 一个简单 iop，写一页“它的参数如何影响输出”的阅读笔记。

## 阅读完成标准

你不需要读懂 darktable 全部代码。完成标准是：能解释一个 iop 模块从参数定义到处理函数的路径，并能说出这种设计如何迁移到 stage3 的 C++ ISP pipeline。

## 项目信息
- GitHub：https://github.com/darktable-org/darktable
- Star 数或活跃度：长期活跃的开源摄影工作流项目，具体 Star 数以 GitHub 页面为准。
- 主要语言：C、C++、Lua、OpenCL

## 项目解决什么问题

darktable 是开源 RAW 照片工作流和暗房软件。它不是一个教学 ISP toy，而是面向真实摄影后期的完整系统，包含 RAW 解码、色彩管理、曝光、降噪、锐化、局部调整、GPU 加速和非破坏式编辑。

## 项目目录结构解读

初学者可以重点看：

- `src/iop/`：image operation modules，很多增强、降噪、颜色模块在这里。
- `src/common/`：图像、颜色、缓存、通用工具。
- `src/develop/`：开发/处理管线相关逻辑。
- `data/`：配置、预设和资源。

## 核心模块说明

darktable 的核心是非破坏式处理管线。用户调整参数时，项目保存的是处理步骤和参数，而不是立即破坏原图。每个 iop 模块类似一个可配置图像处理算子，并由 pipeline 调度。

## 如何和当前项目关联

stage1 和 stage3 都是“显式管线”。darktable 可以作为真实大型项目参考：如何组织模块、参数、缓存、颜色管理和 GPU 加速。

## 值得学习的工程设计

- 非破坏式编辑模型。
- 模块化 image operation。
- CPU/OpenCL 双路径。
- 色彩管理贯穿全流程。

## 初学者阅读顺序

1. 先从用户手册了解处理流程。
2. 再挑一个简单 iop 模块，比如曝光或色调曲线。
3. 看模块参数如何注册、如何进入 pipeline。
4. 最后再看 OpenCL 加速路径。

## 可迁移到当前项目的功能点

1. 给 stage1/stage3 的 pipeline 增加模块参数记录。
2. 把每次处理输出保存为“输入 + 参数 + 版本”的可复现实验记录。
3. 学习 CPU/GPU 双实现的目录组织。

## 阅读后应该掌握什么

你应该能理解：成熟图像项目的难点不只是算法，而是可复现、可配置、可交互和可维护的处理管线。
