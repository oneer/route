>
> 建议用时：3–4 小时阅读 + 2–4 小时实验　|　内容整理：2026-07-19

> **证据提醒**：本章涉及厂商、产品或趋势。正文中的参数必须结合资料日期阅读；公开事实、厂商宣传、第三方分析和合理推断不能混为一类。

## 1. 本章先建立直觉：趋势不会替代基础，而是改变输入、算力和系统边界

ISP 技术发展趋势很容易被写成口号：AI-ISP、事件相机、光场相机、量子图像传感器、神经形态计算、端侧大模型、多模态融合。对初学者来说，更重要的是学会判断一个趋势到底改变了什么。

任何 ISP 趋势都可以放进三个问题里：

- 输入变了吗：还是 Bayer RAW，还是事件流、光场、单光子计数、多光谱、深度、IMU、雷达？
- 处理方式变了吗：还是固定流水线，还是神经网络、多帧优化、异步事件处理、存算一体、近传感器计算？
- 输出目标变了吗：只是 RGB/YUV，还是深度、语义、运动、事件重建、HDR 视频、机器视觉特征？

趋势不是把传统 ISP 全推翻。黑电平、噪声、动态范围、颜色、带宽、延迟、功耗、验证、fallback 这些基础问题仍然存在。新技术真正带来的变化是：数据模型更复杂，计算更靠近传感器，AI 和传统信号处理更深融合，ISP 从“成像模块”逐渐变成“视觉前端系统”。

## 2. 如何判断一个趋势是否真正能落地

工程上不能只看论文效果图，也不能只看厂商宣传。判断趋势成熟度，可以看这张表：

| 判断维度 | 要问的问题 |
|---|---|
| 数据 | 是否有真实数据集？是否覆盖传感器、光照、运动、温度和极端场景？ |
| 算力 | 能否在端侧实时运行？是否需要 NPU/GPU/专用硬件？ |
| 带宽 | 中间数据是否太大？是否需要多帧缓存或高 DDR 带宽？ |
| 功耗 | 长时间运行是否可接受？是否会热降频？ |
| 可解释性 | 出错时能否定位原因？是否有物理约束？ |
| fallback | 模型或新传感器失败时是否能回退到传统路径？ |
| 验证 | 是否有客观指标、主观测试、场景覆盖和安全验证？ |
| 生态 | 是否有驱动、SDK、工具链、标准接口和应用需求？ |

这张表比“新不新”更重要。很多技术在研究里很美，但落地要过数据、硬件、成本和验证。

## 3. 计算摄影硬件化：从单帧 ISP 走向多帧视觉计算

计算摄影已经深刻改变手机、相机和视频系统。典型任务包括：

- 多帧夜景。
- HDR/WDR 融合。
- burst denoise。
- 多帧超分。
- 人像深度与虚化。
- EIS 和 rolling shutter correction。
- 去反射、去模糊、去雨雾。
- RAW 域 learned enhancement。

这些任务共同特点是：不再只处理一帧，不再只做局部滤波，而是要利用时间、空间、语义、运动和多传感器信息。

硬件需求因此改变：

```text
传统ISP：
单帧流式处理 + line buffer + 固定功能模块

计算摄影：
多帧缓存 + 运动估计 + 对齐 + 融合 + AI/NPU + 高带宽调度
```

最现实的发展方向不是用一个大模型替代所有模块，而是异构协同：ISP 负责稳定低功耗基础处理，NPU 负责语义和学习型增强，GPU/DSP 负责几何变换和可编程后处理，Codec/Display 负责视频输出和显示链路。

## 4. AI-ISP：从模块增强到可学习视觉前端

AI-ISP 仍然是最重要趋势之一，但它有不同层级：

- AI 辅助调参：预测 AWB、tone curve、NR 强度、LUT。
- AI 模块增强：去噪、去马赛克、HDR、超分、低照增强。
- 端到端 RAW-to-RGB：直接学习完整 pipeline。
- 任务驱动 ISP：输出不仅给人看，也给检测、分割、SLAM、自动驾驶。
- 可微分 ISP：把 ISP 参数放进训练过程，和下游模型联合优化。

AI-ISP 的难点也很明确：

- 真实 RAW 数据难获得。
- 传感器之间泛化难。
- 极端光照和运动场景难覆盖。
- 视频时域稳定难。
- 端侧部署受算力、带宽、功耗限制。
- 幻觉细节在安全场景不可接受。
- 量化、tile 推理、fallback 和版本管理复杂。

因此未来成熟的 AI-ISP 很可能是混合架构：传统 ISP 保证底线，AI 负责难点增强和内容感知，所有 AI 输出受到物理约束、置信度和回退策略控制。

## 5. 事件相机：从帧图像变成异步事件流

事件相机不按固定帧率输出整张图，而是在像素亮度变化超过阈值时输出事件：

```text
event = (x, y, t, polarity)
```

其中：

- `x, y` 是像素位置。
- `t` 是高精度时间戳。
- `polarity` 表示亮度增加或减少。

事件相机的优势：

- 延迟极低。
- 动态范围高。
- 高速运动场景不容易运动模糊。
- 静态区域不产生大量冗余数据。
- 适合机器人、无人机、高速跟踪、低延迟控制。

事件相机的 ISP 不再是传统 RAW-to-RGB，而是事件流处理：

```text
事件流 -> 去噪/过滤 -> 时间同步 -> 事件累积或表面表示 -> 光流/跟踪/重建 -> 与帧相机融合
```

难点：

- 事件数据稀疏、异步，不适合传统帧 pipeline。
- 静态场景没有事件，不能替代普通相机。
- 噪声事件和背景闪烁需要过滤。
- 和普通帧相机融合时要做时间同步。
- 算法和硬件生态还不如传统相机成熟。

`Event-Based Vision: A Survey` 这类综述强调，事件相机在低延迟、高速和高动态范围场景有潜力，但需要专门算法释放这些特性。

## 6. 光场相机：从 2D 图像变成 4D 光线数据

普通相机记录每个像素位置的光强；光场相机还记录光线方向。常用表示可以写成：

```text
L(x, y, u, v)
```

其中 `x, y` 表示空间位置，`u, v` 表示角度或子孔径视角。光场相机的能力包括：

- 拍后重聚焦。
- 深度估计。
- 视点合成。
- 全聚焦图像。
- 3D/AR/机器视觉。

对 ISP 的影响：

- 输入不再是一张普通 RAW，而是微透镜阵列下的多视角采样。
- demosaic、校准、畸变、微透镜排列都更复杂。
- 空间分辨率和角度分辨率存在取舍。
- 数据量大，重建和深度估计计算量高。
- 需要专门标定主镜头和微透镜阵列。

光场处理不是传统 ISP 的简单扩展，而是把成像问题从 2D 图像处理变成 4D 数据重建。plenoptic camera 相关研究和 EPINET 等 light field depth 工作说明，光场的核心价值在于重聚焦和深度，但硬件、分辨率和计算成本仍是重要限制。

## 7. 量子图像传感器 QIS：每个光子都变成统计问题

Quanta Image Sensor 的核心思想是用极小的 jot 检测光子，甚至接近单光子计数。传统像素输出模拟电荷或多 bit 数值，QIS 更像在高时空分辨率上记录光子到达事件，然后通过局部时空统计重建图像。

可以粗略理解为：

```text
输入：
大量 jot 的二值或多 bit 光子计数数据，带有时间维度

处理：
时空聚合、Poisson统计、去噪、动态范围重建、运动处理

输出：
传统图像像素、HDR图像、低照图像或特殊统计图像
```

QIS 的潜力：

- 极低照度成像。
- 高动态范围。
- 高时间分辨率。
- 通过计算在分辨率、噪声、动态范围之间灵活取舍。

难点：

- 数据率非常高。
- 单光子统计噪声需要新重建算法。
- 传统 ISP 的黑电平、增益、噪声模型都要重写。
- 传感器制造、读出和片上处理压力大。
- 需要新的评价指标和验证方法。

Eric Fossum 等关于 QIS 的综述和论文强调，它是“photon-counting imaging”范式，对超低照和计算重建很有吸引力，但它对应的是新的传感器和新的 ISP。

## 8. 神经形态 ISP：从同步帧处理走向事件驱动计算

神经形态计算模仿神经系统的事件驱动、稀疏、低功耗特性。和事件相机结合时，它的自然输入就是 spike/event。典型处理方式包括脉冲神经网络 SNN、异步计算阵列、事件驱动滤波和低功耗边缘推理。

潜在优势：

- 低延迟。
- 稀疏计算，低功耗。
- 对事件数据天然匹配。
- 适合机器人、无人机、智能传感器和 always-on 视觉。

现实难点：

- SNN 训练和部署生态仍不如 CNN/Transformer 成熟。
- 精度、稳定性和可验证性仍是挑战。
- 传统 ISP 模块很难直接搬到脉冲域。
- 需要专用硬件，通用平台上优势不明显。
- 对初学者来说，先理解事件数据和传统视觉任务更重要。

## 9. 近传感器计算与存算一体：减少数据搬运

ISP 和 AI-ISP 越来越受带宽限制。把完整 RAW 或中间特征图反复搬到 DDR 很耗电。未来趋势之一是把计算靠近数据源：

- sensor-side processing：传感器旁边做简单 HDR、binning、统计、压缩。
- stacked sensor：传感器层 + 逻辑层 + 存储层垂直堆叠。
- processing-in-memory：在存储附近做简单计算。
- near-data computing：减少 DDR 往返。
- on-sensor AI：在传感器或近传感器逻辑中做事件检测、ROI、低功耗唤醒。

它的核心动机不是“更炫”，而是减少数据搬运。未来高分辨率、高帧率、多摄、多帧、AI 的系统里，带宽和功耗可能比算力更早成为瓶颈。

## 10. 多模态融合：ISP 从图像前端变成感知前端

未来视觉系统常常不只用 RGB camera：

- RGB + depth。
- RGB + NIR/IR。
- RGB + event camera。
- RGB + IMU/gyro。
- RGB + radar/lidar。
- RGB + thermal。
- 多摄 + 多焦段。

这会改变 ISP 的定义。它不再只输出“好看的图”，还要输出对下游感知有用的对齐数据：

- 时间同步。
- 空间标定。
- 外参/内参。
- 深度/置信度。
- 运动和姿态。
- ROI/语义。
- 质量评分。

在车载、机器人、AR/VR、无人机和安防里，ISP 更像 perception front-end。评价标准也从“照片是否好看”扩展到“检测、定位、跟踪、建图是否更稳定”。

## 11. 标准化、可验证性和安全：趋势落地的最后门槛

越新的 ISP 趋势，越要问可验证性：

- AI 生成的细节是否可信？
- 事件相机和帧相机时间同步误差是多少？
- 光场深度估计失败时有没有置信度？
- QIS 重建在极低光下是否会产生误导？
- 神经形态输出如何做覆盖率和回归？
- 安全场景是否保留原始证据或可追溯中间数据？

未来 ISP 趋势能否进入车载、医疗、安防、工业，很大程度取决于验证方法，而不是只取决于平均画质。

## 12. 趋势成熟度速查表

| 方向 | 当前成熟度 | 主要价值 | 最大挑战 |
|---|---|---|---|
| 计算摄影多帧 | 高，已广泛商用 | 夜景、HDR、超分、防抖 | 运动、带宽、延迟、热 |
| AI-ISP 模块增强 | 中高，逐步商用 | 去噪、低照、局部增强 | 数据、泛化、部署、fallback |
| 端到端 AI-ISP | 中，研究活跃 | 联合优化 RAW-to-RGB | 可控性、传感器泛化、验证 |
| 事件相机 | 中，特定场景落地 | 高速、低延迟、高动态 | 生态、算法、与帧相机融合 |
| 光场相机 | 中低，专业/研究多 | 重聚焦、深度、多视角 | 分辨率取舍、数据量、成本 |
| QIS | 研究到早期工程 | 单光子、极低照、HDR | 制造、数据率、重建算法 |
| 神经形态 ISP | 研究/探索 | 低功耗事件驱动 | 训练生态、精度、验证 |
| 近传感器计算 | 中，逐步发展 | 降带宽、降功耗 | 工艺、灵活性、工具链 |

## 13. 最小可验证实验

实验 1：趋势成熟度评估

```text
选择 AI-ISP、事件相机、光场、QIS、神经形态中的一个方向。
按数据、算力、带宽、功耗、fallback、验证、生态七项打分。
写出它最适合的应用场景和最大风险。
```

实验 2：事件相机事件触发

```text
事件触发条件：
Δlog(I) > C

设 C = 0.15，I 从 100 到 120。
计算 log(120) - log(100)，判断是否触发事件。
```

实验 3：多帧带宽估算

```text
估算 4K60 12-bit RAW，缓存 5 帧用于多帧融合。
计算输入带宽和缓存读写压力。
解释为什么计算摄影需要异构硬件。
```

实验 4：AI-ISP fallback 设计

```text
假设 AI 低照增强在极暗场景生成假纹理。
设计传统 fallback、置信度判断和输出限制。
```

实验 5：多模态同步表

```text
设计 RGB + event + IMU 的系统。
列出每路数据的时间戳、频率、延迟、坐标系、标定参数和同步风险。
```

## 14. 常见失败现象速查表

| 现象 | 可能原因 | 排查方向 |
|---|---|---|
| AI-ISP 换设备后失效 | 传感器噪声和颜色分布不同 | 检查 RAW 数据、重标定、domain adaptation |
| 事件相机输出太多噪声事件 | 阈值、低照、背景闪烁 | 调事件过滤、时间窗口、阈值 |
| 光场重聚焦模糊或深度错 | 标定不准、微透镜模型错误 | 检查 calibration、EPI、深度置信度 |
| QIS 重建图像颗粒感强 | 光子数太少、聚合窗口不够 | 调时空聚合和 Poisson 模型 |
| 神经形态模型精度低 | 训练方法和任务不匹配 | 对比 ANN/SNN，检查编码方式 |
| 多模态融合错位 | 时间戳、外参、延迟不一致 | 做同步和标定验证 |
| 近传感器计算不灵活 | 固定功能太多，算法变化快 | 保留可配置参数和旁路路径 |
| 新趋势 demo 好看但难量产 | 数据、功耗、验证、生态不足 | 做成熟度表和 failure case |

## 15. 学习优先级

必须掌握：

- 趋势分析要回到输入、处理、输出、验证和部署。
- AI-ISP、事件相机、光场、QIS、神经形态分别改变了什么数据模型。
- 带宽、功耗、实时性和 fallback 决定趋势能否落地。
- 安全场景更重视可解释、可验证和不 hallucinate。
- 多模态融合要求时间同步、空间标定和置信度。

了解即可：

- QIS 的完整单光子统计推导。
- SNN 的全部训练算法。
- 光场相机完整几何模型。
- 事件相机所有表示方法和 benchmark。
- 各厂商最新芯片的营销名称。

后面再回看：

- 可微分 ISP。
- neural rendering 与 computational photography。
- event-based SLAM/optical flow。
- light field depth and refocusing。
- photon-counting reconstruction。
- neuromorphic hardware。
- sensor-processor 3D stacking。

## 17. Gotchas：初学者最容易踩的坑

- 把趋势当口号，不分析输入数据和系统约束。
- 以为 AI-ISP 可以跳过传统 ISP 基础。
- 只看论文样张，不看真实数据、功耗和端侧部署。
- 认为事件相机可以替代普通相机，忽略静态场景信息不足。
- 认为光场相机只多一个重聚焦功能，忽略分辨率和数据量取舍。
- 认为 QIS 只是一种更灵敏传感器，忽略统计重建和数据率。
- 认为神经形态必然低功耗，忽略生态、精度和硬件限制。
- 多模态融合只做空间标定，忽略时间同步。
- 新技术没有 fallback，就直接用于安全关键场景。

## 18. 读完本章的验收标准

读完后，你应该能做到：

- 用“输入、处理、输出、部署、验证”五个维度分析任一 ISP 新趋势。
- 解释计算摄影、AI-ISP、事件相机、光场、QIS、神经形态的核心变化。
- 给每个趋势列出至少一个应用场景和一个最大工程风险。
- 用简单带宽或事件触发计算说明趋势背后的系统压力。
- 设计一个小型验证计划，而不是只说“这个方向有前景”。
- 判断一个新技术更接近研究原型、特定场景落地，还是大规模商用。

- Event-Based Vision: A Survey：理解事件相机的低延迟、高动态范围和事件流算法生态。

- NVIDIA VPI、libcamera、Android Camera HAL、V4L2：理解新趋势最终仍要接入真实视觉系统和软件栈。
