>

## 1. 本章先解决什么问题

车载 ISP 真正困难的不是晴天白天，而是“最容易让感知系统失效”的边界场景：雨、雾、雪、夜间、隧道口、强逆光、LED 闪烁、运动模糊、镜头脏污、温度漂移。这些场景不是单纯让图像不好看，而是可能让车道线、行人、车辆、交通灯、路牌和障碍物变得不可见或被错误增强。

本章要建立一个思维方式：

```text
场景问题
-> 图像退化现象
-> 影响哪些感知任务
-> 对应哪些 ISP / sensor / fusion 策略
-> 可能产生什么副作用
-> 如何验证
```

读完本章，至少要能回答：

- 雾、雨、雪分别怎样退化图像。
- 夜间增强为什么不能只拉亮。
- LED Flicker Mitigation 为什么是车载核心能力。
- 运动模糊、卷帘快门和 HDR 鬼影有什么关系。
- 去雾、去雨、锐化、HDR、AI 增强为什么可能伤害感知。
- 如何为特殊场景建立测试表和验收标准。

## 2. 特殊场景不能只按“看起来更清楚”评价

车载 ISP 的特殊场景优化要同时看人眼和机器：

| 目标 | 关心什么 |
|---|---|
| 驾驶员显示 | 画面自然、低眩光、低延迟、不刺眼 |
| ADAS 感知 | 目标可检测、边缘稳定、颜色可信、少伪影 |
| 记录取证 | 时间戳准确、关键目标清楚、压缩前质量可靠 |
| 安全系统 | 异常可诊断、可降级、不会静默失败 |

比如去雾算法把对比度拉高，人眼会觉得清楚，但如果它制造了假边缘，车道线检测或目标检测可能误报。夜景增强把暗部拉亮，人眼觉得“亮”，但如果把黑夜变成白天，算法对路灯、车灯、行人反光的判断可能改变。

所以每个增强都要问：

```text
它增强了什么？
它破坏了什么？
它是否改变了训练数据分布？
它是否逐帧稳定？
它在最坏场景下是否会输出误导性图像？
```

## 3. 场景到 ISP 策略的总表

| 场景 | 典型退化 | 相关模块 | 主要风险 |
|---|---|---|---|
| 雾/霾 | 对比度低、远处泛白、颜色偏灰 | dehaze、local contrast、tone mapping | 过增强、假边缘、远处噪声放大 |
| 雨滴 | 局部模糊、折射、遮挡 | raindrop detection、inpainting、多帧融合 | 把真实目标当雨滴抹掉 |
| 雪 | 高亮点/条纹、遮挡、低对比 | 时空滤波、运动分割、曝光控制 | 把车灯/路牌误判为雪 |
| 夜间 | 低 SNR、车灯眩光、暗部缺失 | low-light NR、HDR、NIR/IR fusion | 细节涂抹、黑位抬高、色偏 |
| LED 闪烁 | 条纹、帧间亮灭、交通灯缺失 | LFM、曝光控制、sensor HDR | 曝光变长导致运动模糊 |
| 隧道口 | 极端明暗、AE 突变 | HDR、快速 AE、local tone mapping | 鬼影、亮度跳变、过压高光 |
| 高速运动 | 模糊、rolling shutter、目标拉伸 | 短曝光、motion compensation、IMU | 短曝光噪声上升 |
| 强眩光 | 光斑、flare、饱和、对比下降 | highlight suppression、lens design、HDR | 目标被高光吞掉 |
| 脏污遮挡 | 局部模糊/暗斑/水膜 | obstruction detection、diagnostics | 系统未报警继续使用坏图 |
| 高低温 | 黑电平漂移、暗电流、坏点增加 | temperature compensation、calibration | 标定失效、颜色/噪声不稳 |

这张表是本章最重要的学习工具。

## 4. 雾和霾：去雾不是简单提高对比度

雾天图像常见现象：

- 远处目标对比度下降。
- 颜色变灰、饱和度降低。
- 天空和远景接近大气光颜色。
- 车道线、行人、车辆轮廓变弱。

经典大气散射模型：

```text
I(x) = J(x) * t(x) + A * (1 - t(x))
```

其中：

- `I(x)` 是观测图像。
- `J(x)` 是无雾场景。
- `t(x)` 是透射率，远处通常更小。
- `A` 是大气光。

暗通道先验、Retinex、CLAHE、深度学习去雾都可以改善可见度，但车载场景要特别小心：

- 远处噪声会被放大。
- 天空和路面可能出现不自然块状。
- 车道线边缘可能被过度锐化。
- 检测模型如果没见过这种增强风格，可能性能下降。

因此车载去雾更适合“轻增强 + 稳定输出 + 感知验证”，而不是追求视觉上最清晰。

## 5. 雨滴：镜头上的雨和空中的雨不是一回事

雨天问题分两类：

```text
附着雨滴：在镜头/挡风玻璃上，位置相对固定，造成局部模糊和折射。
空中雨线：在场景中运动，表现为细线、亮 streak 或时域噪声。
```

附着雨滴会严重影响：

- 交通灯区域被遮挡。
- 车道线局部断裂。
- 远处车辆轮廓被扭曲。
- 环视相机局部区域失效。

MDPI 的 automotive raindrop survey 指出，挡风玻璃上的附着雨滴会影响 object recognition、traffic sign recognition、localization、mapping 等 ADAS 任务。这说明雨滴不是画质小问题，而是感知链路问题。

常见处理：

- 检测雨滴 mask。
- 对显示图做局部修复。
- 对感知图输出置信度或遮挡区域。
- 多摄/多帧补偿。
- 严重时触发清洁、加热或降级。

注意：不能随意把被雨滴遮挡的区域“修成看起来像路面”，因为这可能给感知系统制造不存在的证据。对于安全相关感知，标记不可信区域有时比“修复得好看”更重要。

## 6. 雪：动态遮挡和高亮干扰

雪比雨更复杂：

- 雪花可能大、亮、近，遮挡目标。
- 前照灯照亮雪花后会形成亮点和条纹。
- 地面积雪会改变车道线和路沿对比。
- 雪景整体高亮，AE 可能误判。

处理思路：

- 用时域信息区分短暂雪花和稳定目标。
- 对高亮小目标做运动一致性判断。
- 调整 AE，避免雪地被压成灰。
- 保留车道线和边界细节，避免强降噪抹平。
- 感知模型需要雪天数据增强和真实测试。

风险：

- 把远处车灯误当雪花。
- 把雪地纹理增强成假车道线。
- 把积雪覆盖后的路沿误判为可行驶区域。

雪天优化不能只在 ISP 层解决，必须和感知算法、地图、雷达/激光雷达融合一起验证。

## 7. 夜间：低光增强的核心是 SNR 和眩光

夜间图像同时有两类极端：

```text
暗部：光子少，噪声大，目标弱。
亮部：车灯、路灯、反光标志很亮，容易饱和和眩光。
```

夜间增强要处理：

- 降噪。
- 保边缘。
- 防车灯眩光。
- 保交通标志反光信息。
- 稳定白平衡。
- 避免运动模糊。

低照增强不能只拉亮。拉亮暗部会放大噪声，强降噪会抹掉行人、车道线和小目标。Learning to See in the Dark 这类低光论文说明 RAW 域低光增强有很大潜力，但车载实时系统还要考虑低延迟、模型可靠性、温度、训练数据覆盖和功能安全。

工程上常用组合：

```text
短曝光控制运动模糊
+ 高灵敏度传感器 / 大像素 / NIR
+ 多帧或时域降噪
+ 高光保护
+ 感知模型夜间专项训练
```

## 8. NIR / IR 夜视：解决可见光不足，但不是万能

近红外 NIR、远红外 FIR/LWIR 可以改善夜间行人和障碍物识别。NIR 系统常配合主动照明，LWIR 看到的是热辐射。

优势：

- 夜间行人更容易从背景中分离。
- 对可见光眩光不完全敏感。
- 与可见光图像互补。
- 可以给 AEB 或行人预警提供额外证据。

挑战：

- 可见光与 NIR/IR 需要几何配准。
- 不同光谱下同一物体外观差异很大。
- 水汽、玻璃、雨雾会影响不同红外波段。
- 传感器成本、分辨率、标定和清洁维护不同。

多光谱融合常见层次：

```text
像素级融合：直接合成图像。
特征级融合：分别提取特征再融合。
决策级融合：各自检测后合并结果。
```

对于安全感知，特征级或决策级融合往往更可控，因为不会强行制造一张“看似自然”的假彩色图像。

## 9. LED Flicker：交通灯不能在某些帧中消失

LED 交通灯、车灯、可变道路标志可能使用 PWM 调光。相机是离散采样系统，如果曝光时间和 LED 周期不匹配，会出现：

- 交通灯帧间亮灭。
- rolling shutter 条纹。
- LED 标志局部缺失。
- 颜色和亮度测量不稳定。

Sony LFM 技术资料强调 LFM 用于抑制拍摄 LED 交通灯和标志时产生的 flicker；onsemi 的 split-pixel / super-exposure pixel 白皮书也把 HDR 和 LFM 作为严苛车载环境的重要需求。IEEE P2020 相关资料也讨论了 LED flicker measurement 的挑战。

工程策略：

- 传感器层 HDR + LFM pixel。
- 曝光时间覆盖 LED 周期。
- 多曝光中保留长曝光信息。
- flicker detection。
- 避免 rolling shutter 与 PWM 形成条纹。

代价：

- 曝光变长会增加运动模糊。
- 长曝光高光更容易饱和。
- HDR 与 LFM 的曝光策略可能冲突。

因此 LFM 不是普通手机防频闪，它直接关系到交通灯、刹车灯、警示灯是否被可靠识别。

## 10. 隧道出入口：AE 和 HDR 的压力测试

隧道出入口是车载 ISP 经典最坏场景：

```text
进隧道：画面从亮到暗，AE 要快速提高曝光但不能闪。
出隧道：暗背景前方突然强光，HDR 要保出口细节。
隧道内：LED 灯频闪、车灯眩光、低照噪声同时存在。
```

失败现象：

- 出口完全过曝，看不到前车。
- 隧道内部全黑，看不到车道线。
- AE 快速跳变导致视频闪烁。
- LED 标志条纹或消失。
- HDR 多曝光产生运动鬼影。

优化策略：

- sensor 侧宽动态。
- staggered HDR 或 split pixel HDR。
- 快速但平滑的 AE。
- 局部 tone mapping 保护路面和交通灯。
- 对感知输出保留线性或弱 tone mapping 版本。
- 用场景识别提前切换策略。

隧道场景要用视频序列验证，不能只用单张图。因为收敛速度、帧间稳定和延迟同样重要。

## 11. 运动模糊：短曝光、噪声和 LFM 的三角关系

高速驾驶时，运动模糊来自：

- 自车运动。
- 目标运动。
- 车辆振动。
- rolling shutter 行读出。
- 曝光时间过长。

减少运动模糊最直接的方法是缩短曝光时间，但这会让图像变暗、噪声增加，并可能影响 LFM。于是出现三角矛盾：

```text
短曝光：运动清楚，但噪声高，LED 采样可能不完整。
长曝光：亮度好，LFM 更容易，但运动模糊。
高增益：亮度上来，但噪声和动态范围变差。
```

车载 AE 必须根据车速、光照、LED 场景、目标任务做取舍。例如 AEB 场景更关心行人/车辆轮廓清晰，电子后视镜更关心显示稳定，记录仪可能更关心可读车牌。

## 12. Rolling Shutter：不是后期拉直就完了

rolling shutter 逐行曝光，车辆运动或振动会造成：

- 竖直物体倾斜。
- 快速车辆变形。
- LED 条纹。
- 多摄时间对齐变复杂。
- BEV 或目标定位误差。

校正需要：

- 每行曝光时间模型。
- IMU/陀螺仪同步。
- 车速和相机姿态。
- 逐行几何 warping。
- 与 perception timestamp 对齐。

如果只是把显示图拉直，但 metadata 没有同步更新，感知系统仍可能使用错误几何。因此 rolling shutter 校正要和标定、时间戳、IMU 一起看。

## 13. HDR 鬼影：车载多曝光最怕运动

多曝光 HDR 常把短曝光和长曝光合成。问题是车载场景里几乎总有运动：

- 自车在动。
- 对向车在动。
- 行人横穿。
- 交通灯和标志相对移动。
- rolling shutter 造成行间时间差。

如果对齐或权重不对，会产生 ghosting：

- 车辆边缘双影。
- 行人轮廓重叠。
- 车灯拖影。
- 标志文字模糊。

处理策略：

- 选择参考曝光。
- motion mask。
- 局部使用单曝光替代融合。
- 对饱和高光单独处理。
- 对交通灯/车灯保留短曝光信息。
- 优先保证感知目标边界清楚，而不是全图 HDR 好看。

HDR 在车载里不是摄影效果，而是感知信息保真问题。

## 14. 脏污、遮挡和水膜：检测比修复更重要

镜头脏污包括：

- 泥点。
- 水滴。
- 油膜。
- 霜雾。
- 昆虫。
- 划痕。
- 雪覆盖。

它们会造成局部模糊、暗斑、散射、眩光和遮挡。对安全系统来说，最危险的是系统不知道自己看不清。

因此车载 ISP 或上层视觉系统需要 obstruction detection：

- 长时间固定模糊区域。
- 局部对比度异常低。
- 局部亮度/颜色异常。
- 多帧中遮挡位置相对固定。
- 与其他摄像头或传感器不一致。

严重时应：

- 降低该区域感知置信度。
- 通知上层降级。
- 提示清洁或启用加热/雨刷/喷洗。
- 禁用依赖该相机的功能。

不要把严重遮挡区域“AI 修复”后继续用于安全决策。

## 15. 特殊场景优化的验证方法

车载特殊场景验证要覆盖：

| 验证类型 | 内容 |
|---|---|
| 场景覆盖 | 雾、雨、雪、夜、隧道、眩光、LED、脏污 |
| 亮度范围 | 低照到强阳光，动态范围边界 |
| 速度 | 低速泊车、高速道路、横穿目标 |
| 温度 | 低温启动、高温暴晒、长时间运行 |
| 时间 | 单帧质量、视频稳定、AE/AWB 收敛 |
| 任务指标 | 检测率、误报率、车道线稳定、交通灯识别 |
| 安全 | 异常检测、降级、日志和故障注入 |

验证时不要只看增强后图像，要同时跑感知模型。最终指标应该包括：

- 目标检测 mAP / recall。
- 交通灯识别准确率。
- 车道线稳定度。
- 误报率。
- 延迟。
- 帧间 flicker。
- 失败检测率。

## 16. 最小可验证实验

实验 1：场景映射表。

1. 建一张表：场景、退化现象、相关 ISP 模块、副作用、验证方法。
2. 至少填雾、雨、雪、夜、LED、隧道、脏污七类。
3. 每类写一个“增强过头”的风险。
4. 每类写一个感知任务指标。

实验 2：去雾副作用观察。

1. 选雾天道路图像。
2. 分别用 CLAHE、暗通道、学习型去雾或简单对比增强。
3. 观察远处噪声、天空块状、车道线边缘。
4. 用边缘检测或目标检测看是否产生假边缘。

实验 3：LED flicker 采样。

1. 拍摄 LED 灯或 PWM 光源。
2. 改变曝光时间和帧率。
3. 观察条纹、亮灭和 rolling shutter。
4. 写出 LFM 为什么需要传感器/曝光策略支持。

实验 4：夜间增强取舍。

1. 选夜间道路视频。
2. 分别测试拉亮、降噪、锐化、HDR 风格增强。
3. 观察行人、车道线、车灯、标志牌。
4. 记录哪个处理让人眼更舒服，哪个更适合检测。

实验 5：脏污检测。

1. 模拟固定水滴或污点遮挡。
2. 连续帧中计算局部清晰度和纹理变化。
3. 判断哪些区域长期异常。
4. 设计输出：mask、置信度、告警、降级策略。

## 17. 错误现象排查表

| 现象 | 可能原因 | 排查方向 |
|---|---|---|
| 雾天远处噪声很强 | 去雾或对比增强过度 | 看透射率估计、增益、远景区域 |
| 雨滴区域生成假目标 | 修复算法过度想象 | 输出遮挡 mask，不给安全感知用修复区域 |
| 雪天车道线误检 | 高亮雪纹理被增强 | 检查锐化、边缘增强、模型雪天数据 |
| 夜景像白天但误检多 | 黑位抬高和噪声放大 | 检查低照增强强度和检测输入 |
| 交通灯某些帧消失 | LED flicker / LFM 不足 | 检查曝光时间、PWM、sensor LFM |
| 隧道出口全白 | HDR 不足或 AE 反应慢 | 检查短曝光、高光饱和、tone mapping |
| 车辆边缘双影 | HDR 多曝光鬼影 | 检查 motion mask、参考帧、融合权重 |
| 高速场景车牌糊 | 曝光过长或振动 | 检查 AE、快门、OIS/IMU、rolling shutter |
| 脏污镜头未报警 | obstruction detection 缺失 | 做固定遮挡和水膜测试 |
| 增强后模型性能下降 | ISP 改变训练分布 | 用任务指标评估，不只看图像观感 |

## 18. 常见误区

- 误区 1：特殊场景优化就是让图更清楚。车载要看感知任务是否更可靠。
- 误区 2：去雾越强越好。过强去雾会放大噪声和假边缘。
- 误区 3：夜间增强就是拉亮。拉亮会放大噪声，改变黑位和灯光语义。
- 误区 4：LED flicker 只是视频观感问题。交通灯/刹车灯识别会直接受影响。
- 误区 5：AI 修复脏污区域很先进。安全系统更需要知道哪里不可信。
- 误区 6：HDR 一定改善感知。运动鬼影和 tone mapping 也会伤害目标边界。
- 误区 7：单帧样张好就通过。特殊场景必须看视频稳定、延迟和最坏条件。
- 误区 8：ISP 可以独立解决所有恶劣天气问题。很多场景需要 radar/lidar/IR 和感知模型共同处理。

## 19. 学习优先级

必须掌握：

- 雾、雨、雪、夜间、LED、隧道、运动模糊、脏污的图像退化机制。
- HDR、LFM、低照增强、去雾、去雨、NIR/IR 融合的基本作用和副作用。
- 特殊场景优化要用感知任务指标验证。
- 安全相关场景下，标记不可信区域往往比美化修复更重要。
- 视频序列稳定性比单帧效果更关键。

了解即可：

- 暗通道去雾、Retinex、CLAHE、guided filter 的具体实现。
- 深度学习低光、去雨、去雾网络结构。
- 多光谱融合、NIR/LWIR 行人检测算法。
- IEEE P2020 对 automotive image quality 的测试方向。
- 车规传感器 HDR/LFM pixel 具体电路。

后面再回看：

- 恶劣天气数据集和仿真。
- ISP 与感知模型联合训练。
- 端到端可微 ISP 在车载中的安全风险。
- SOTIF 场景库和 corner case 挖掘。

## 20. 自测题

1. 雾天图像为什么远处对比度更低？
2. 去雾算法为什么可能制造假边缘？
3. 附着雨滴和空中雨线有什么区别？
4. 夜间增强为什么不能只提高亮度？
5. NIR/IR 夜视相比可见光有什么优势和限制？
6. LED flicker 为什么会让交通灯在相机里消失或条纹化？
7. 隧道出入口为什么同时考验 AE、HDR 和 tone mapping？
8. 短曝光、低噪声、LFM 之间有什么矛盾？
9. HDR 鬼影为什么在车载场景里特别危险？
10. 为什么脏污遮挡更应该检测和降级，而不是只做图像修复？

## 21. 读完本章的验收标准

合格的学习结果应该是：

- 能把至少 8 类车载特殊场景映射到图像退化、ISP 策略和验证指标。
- 能解释大气散射、LFM、低光 SNR、运动模糊、HDR 鬼影的基本机制。
- 能说清每类增强算法的副作用。
- 能设计一套特殊场景测试表，而不是只看普通样张。
- 能根据交通灯闪烁、雨滴遮挡、隧道过曝、夜间误检等现象提出排查方向。
- 能说明为什么车载特殊场景必须和感知模型、诊断和降级策略一起验证。

## 22. 推荐资料与进一步阅读

- [Sony Semiconductor：LED Flicker Mitigation Technology for Automotive Use](https://www.sony-semicon.com/en/technology/automotive/lfm.html)：理解车载 LFM 为什么面向交通灯和 LED 标志。
- [onsemi：Super-Exposure Pixels Mitigate LED Flicker in Automotive Environments](https://www.onsemi.com/download/white-papers/pdf/tnd6449-d.pdf)：理解 split-pixel / super-exposure pixel 如何服务 HDR 和 LFM。
- [Automotive 3.0 µm Pixel High Dynamic Range Sensor with LED Flicker Mitigation](https://www.mdpi.com/1424-8220/20/5/1390)：HDR + LFM 车载传感器论文，包含温度、暗电流和图像质量讨论。
- [A Review of Detection and Removal of Raindrops in Automotive Vision Systems](https://www.mdpi.com/2313-433X/7/3/52)：系统了解雨滴对 ADAS 任务的影响和检测/去除方法。
- [HDR CMOS Image Sensors for Automotive Applications](https://www.researchgate.net/publication/360193779_HDR_CMOS_Image_Sensors_for_Automotive_Applications)：理解车载 HDR CIS、LED flicker、motion artifacts 等问题。
- [Learning to See in the Dark](https://arxiv.org/abs/1805.01934)：低光 RAW 域增强代表性论文，可用于理解低照增强潜力和限制。
- [Fusion of Multispectral Data Through Illumination-aware Deep Neural Networks for Pedestrian Detection](https://arxiv.org/abs/1802.09972)：理解可见光/红外多光谱融合对夜间行人检测的作用。
- [ISET-LFM: Physics-based Simulation Framework and Dataset for LED Flicker in Automotive Imaging](https://library.imaging.org/ei/articles/38/16/AVM-105)：LED flicker 仿真和数据集方向，适合进一步研究验证方法。
