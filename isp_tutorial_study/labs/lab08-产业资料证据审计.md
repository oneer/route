# Lab 08：产业平台资料证据审计

对应章节：17–24。

## 目标

把厂商宣传、官方规格、论文、第三方实测和合理推断分开，避免背诵过时参数或不可验证内部结构。

## 任务

任选一个移动、车载或专业相机平台，建立证据卡：

| 项目 | 内容 |
|---|---|
| 平台/型号/软件版本 |  |
| 资料截至日期 |  |

| 论文/专利 `[S2]` |  |
| 第三方可复现实测 `[S3]` |  |
| 合理推断 `[S4]` |  |
| 宣传指标 `[S5]` |  |
| 仍然未知/待核实 |  |

## 强制核查问题

1. “最高像素”是否说明帧率、ZSL、HDR、位深和并发相机数量？
2. TOPS 属于 ISP、NPU、GPU 还是整个 SoC？精度是什么？
3. 功耗是模块、SoC 还是整机？峰值还是持续？测试条件是什么？
4. “支持”是否依赖 OEM、SDK、license 或特定 sensor mode？
5. 内部流水级数、cache、总线宽度是否有一手公开依据？

## 对照案例

阅读第 18 章原文归档中 A17 Pro 的具体内部数字，再对照 Apple 官方公开资料。将每个结论标成 `[S1]`–`[S5]` 或 `[待核实]`，不得用“官方没否认”作为证据。

## 验收

- 至少使用两个不同域名的一手来源，并记录发布日期/访问日期。
- 每条推断写出前提和可能的替代解释。
- 不使用无日期的“最新”“领先”作结论。
- 最终选型理由包含接口、工具链、安全、生态和验证能力，而不只比较峰值参数。
