# ISP 从原理到工程：可验证学习课程

本目录把原 35 章长文重构为一套可自学、可实验、可复习、可追溯的 ISP 课程。课程目标不是继续堆叠知识点，而是形成统一闭环：

```text
理解问题 → 明确输入输出 → 运行实验 → 观察失败案例 → 用指标验收 → 连接工程项目
```

原始来源：[ISP IP 设计教程：从算法到 RTL 实现](https://zsc.github.io/isp_tutorial/)。原网页正文保留在 `source_archive/`，学习时应优先使用经过重组的 `study_chapters/`。

## 从这里开始

1. 查看 [课程路线](COURSE_ROADMAP.md)，选择核心路线或方向选修。
2. 从 [完整课程索引](full_content_index.md) 进入学习版章节。
3. 第一次动手前完成 [Lab 01：RAW 与传感器身份契约](labs/lab01-raw与传感器身份契约.md)。
4. 每章至少完成一次自测，并用对应答案页的 rubric 评分。
5. 遇到图像现象时对照 [ISP 视觉图谱](VISUAL_ATLAS.md)，不要只看整图或单一指标。

## 四条学习路线

- **传统 ISP 核心路线**：第 1–16、32、34 章。适合建立 RAW、pipeline、3A、硬件与验证基础。
- **AI-ISP 路线**：核心路线 + 第 28–30、32、34 章，并连接 `stage2_ai_isp` 和 `stage4_deploy_isp`。
- **硬件/系统路线**：第 1–14、30、32–34 章，并连接 `stage3_cpp_isp`、部署和系统综合项目。
- **车载/行业路线**：核心路线 + 第 20–22、32、34 章；第 17–27 章其余内容按岗位选修。

第 17–27 章的厂商和场景分析不是入门前置知识。先掌握第 1–16 章，再用统一证据模板阅读产业内容。

## 每章完成定义

一章只有满足以下条件才算完成：

- 能用自己的话解释本章为什么存在。
- 能写出输入、处理、输出、位深/数据域或系统边界。
- 能说明至少两个失败现象及排查顺序。
- 完成配套实验并保存命令、配置、输出和指标。
- 自测达到 8/10，或记录未掌握项并回看。
- 能指出本仓库中对应的实现、测试、报告或暂缺部分。

## 内容可信度

厂商章节、趋势章节和性能数字遵循 [来源与时效分级规范](SOURCE_POLICY.md)。未经一手资料证实的内部结构只能作为推断或原文观点，不能当作确定事实。产业资料的默认审查日期为 **2026-07-19**。
