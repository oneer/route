# ISP 自学课程质量标准

目标：让读者从“看过知识点”推进到“能解释、能运行、能观察失败、能用指标验收、能连接工程项目”。篇幅不是完成度指标。

## 1. 文档职责必须分开

- `study_chapters/`：教学主线，只保留经过重组的导学内容和学习闭环。
- `source_archive/`：原教程资料归档，不承担准确性和时效性保证。
- `full_chapters/`：稳定入口，不再塞入长正文。
- `labs/`：可执行实验。
- `answer_keys/`：答案要点和评分 rubric。

学习版不得再次复制整篇原文，避免重复、层级混乱和事实冲突。

## 2. 每章开头必须回答

- 为什么学：解决什么问题，在 pipeline 或系统中的位置。
- 学习结果：能解释、判断、实现或验证什么。
- 难度、优先级、预计阅读/实验时间。
- 输入、处理、输出和关键前置假设。
- 内容日期；产业章节必须增加证据提醒。

## 3. 核心概念必须有四层解释

| 层次 | 要求 |
|---|---|
| 直觉 | 对应什么物理现象、图像现象或系统需求 |
| 工程 | 在数据、代码、RTL、寄存器、格式或指标中如何体现 |
| 失败 | 做错会出现什么画质、性能、稳定性或安全问题 |
| 验证 | 用什么输入、对照、指标和 crop 证明理解正确 |

## 4. 公式必须可计算

- 解释每个变量、单位、取值范围或典型数量级。
- 至少给一个最小数值例子或边界例子。
- 说明公式适用条件和不适用场景。
- 关联到代码、硬件或测量步骤。
- 位宽公式必须说明舍入、饱和、溢出和 Q 格式。

## 5. 实验必须可复现

每个实验必须同时具备：

```text
固定输入 + 完整命令 + 配置/版本 + 输出路径 + 对照组 + 数值指标 + 固定 crop + 验收判据
```

仅写“找一张图片、尝试几个参数、观察效果”不算完整实验。无法在当前仓库执行的内容必须标为“纸面实验”或“外部平台依赖”。

## 6. 必须连接本项目

每章至少指出以下之一：

- Stage 1 的传统 ISP 实现、脚本、数据或 IQ 报告。
- Stage 2 的训练、测试、指标或失败案例。
- Stage 3 的 C++ 对齐、定点或 benchmark。
- Stage 4 的部署、量化、延迟或内存。
- 综合项目的 IQ、多摄、系统性能或回归。
- 暂无实现时，明确最小补充任务及暂缺原因。

## 7. 自测必须有反馈

- 自测覆盖为什么、输入输出、模块顺序、参数后果和验证设计。
- 每章必须链接对应答案要点。
- 开放题按假设、证据和推理评分，不要求唯一措辞。
- 统一 10 分制，8 分通过；低于 8 分应记录未掌握项。

## 8. 图像内容必须有视觉证据

- 算法章节至少提供一组成功/失败对照或链接到视觉图谱。
- 固定相同输入、crop、缩放、显示变换和色彩管理。
- 不能只给整图；至少覆盖暗部、边缘、纹理、颜色、高光或运动中的相关区域。
- AI 和视频章节必须保留 failure gallery 与时域检查。

## 9. 产业事实必须可追溯

- 使用 `[S1]`–`[S5]` 和 `[待核实]` 标签，具体见 [SOURCE_POLICY.md](SOURCE_POLICY.md)。
- 不使用无日期的“最新”“领先”。
- 平台能力、OEM 启用、SDK 支持和实际产品效果必须区分。
- TOPS、像素率、功耗和 benchmark 必须说明对象、精度、条件和来源。
- 无法从公开资料确认的内部 cache、总线、流水级等不得写成确定事实。

## 10. Markdown 结构与维护

- 每个文件只有一个 H1，标题层级不跳级。
- 所有代码块注明 `python`、`powershell`、`cpp`、`verilog`、`text` 等类型。
- 本地链接必须存在，章节必须有上一章/下一章/索引导航。
- 网页抓取 HTML 只允许保留在归档区；学习版优先使用标准 Markdown。
- 每次更新产业章节要修改资料日期；每次更新实验要重跑对应命令和回归。

## 11. 章节完成门禁

| 门禁 | 必须通过 |
|---|---|
| 内容 | 为什么、输入输出、原理、失败和取舍齐全 |
| 实验 | 命令可运行或清晰标注外部依赖，输出可复现 |
| 视觉 | 有固定 crop/曲线/failure case |
| 评价 | 质量与性能至少各有一个有效证据，或说明不适用 |
| 自测 | 有题、有答案 rubric、达到 8/10 |
| 工程 | 至少一个本仓库项目落点 |
| 来源 | 关键结论可追溯，产业内容有日期和证据等级 |
| 文档 | 无断链、标题不跳级、代码块闭合 |

一句话标准：读者完成一章后，应能说明“为什么存在、吃什么吐什么、做错会怎样、怎样复现和验收、在工程里落在哪里”。
