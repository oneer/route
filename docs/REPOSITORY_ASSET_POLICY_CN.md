# 仓库资产管理策略

## 1. 目标

仓库应让新贡献者在不下载完整数据集和历史实验输出的情况下，完成源码审查、单元测试和合同回归。大型资产必须可追踪，但不默认进入 Git 主历史。

## 2. 资产分级

1. 源码、配置、测试、manifest、报告结论：直接 Git 跟踪。
2. 小型 golden fixture：可直接 Git 或 Git LFS 跟踪；每个测试只保留满足回归所需的最小样本。
3. 代表性图片：每项实验保留少量输入、输出、误差图和失败案例。
4. 完整实验输出：放 GitHub Release、对象存储或独立 artifact 包；仓库保留生成命令、hash 和结果 CSV。
5. 数据集：不提交完整副本；保留来源、许可证、下载/准备脚本和机器可读 split manifest。
6. 模型与 TensorRT engine：ONNX 小模型可按需 LFS；checkpoint 和 engine 默认外置。TensorRT engine 必须注明硬件与软件版本，不能视为通用资产。
7. 论文、网页正文和 PDF 导出：只有在许可证明确允许再分发时才能提交；否则只保留链接、引用信息和个人笔记。

## 3. 提交前检查

1. 运行 `powershell -File tools/audit_repository.ps1` 查看文件数量、LFS 数量和大文件排行。
2. 运行 `git status --short`，确认没有数据集、checkpoint、build 或临时输出。
3. 新增二进制资产时记录来源、生成命令、SHA-256 和保留理由。
4. 一个结果能由 CSV 和 3 张代表图说明时，不提交数百张同类图。

## 4. 历史资产迁移规则

现有被 Git 跟踪的资产不在普通整改中直接删除，也不重写 Git 历史。迁移分三步：先生成清单与 hash，再上传外部存储并验证下载，最后由仓库所有者审批删除或历史清理。
